# Midi Fadester — Requirements

Status: 2026-10-27. Approved by the operator on 2026-10-27 with Phase 1 scope tightened to solve the core fader problem end-to-end first, and advanced mixer features ordered into Phases 2–5 (decisions recorded in Section 9).
Companion to [PLAN.md](PLAN.md); requirement IDs (`R-*`) and operator decisions (`D-*`) are referenced across the plan, test suite, and commit messages.

**Midi Fadester** (`midi-fadester.dll`) is a native C/C++ plugin for OBS Studio 33 on Windows x64 that gives class-compliant MIDI controllers—starting with the **Akai APC40 mkII**—direct, continuous fader control over OBS Studio Mode T-bar crossfades, two-source dip-free layer crossfades, single-layer opacity fades, and cubic-dB audio levels with 30 ms slew smoothing, 14-bit CC support, and soft takeover (Phase 1), followed by multi-strip `Thru | Bus A | Bus B` mixing, filter modulation, and hotkeys (Phase 2), hardware blend modes, Luma Key, and Wipe faders (Phase 3), a dockable mixer UI (Phase 4), and APC40 mkII RGB LED feedback (Phase 5).

| `R-MIDI-5` | **Phase 1** | **7-Bit / 14-Bit Continuous Resolution & Per-Control Auto-Widening Calibrated Range:** Every bound continuous control stores calibrated raw extremes `[cal_min, cal_max]` persisted per profile and control, defaulting to `[0, 127]` for 7-bit CC and `[0, 16383]` for 14-bit CC pairs (`CC 0..31` MSB + `CC 32..63` LSB) and Pitch Bend. #### 5.1.1 Studio Mode T-Bar State Machine (`R-TBAR-SM`, Zero Timers)

Coordinates: `raw` is the control's raw MIDI value; `[cal_min, cal_max]` are the control's persisted calibrated extremes per profile and control (`R-MIDI-5`, default `[0, 127]` for 7-bit CC and `[0, 16383]` for 14-bit CC/Pitch Bend, auto-widening whenever `raw < cal_min` or `raw > cal_max`); $x = \text{clamp}_{[0,1]}\big((\text{raw} - \text{cal\_min}) / (\text{cal\_max} - \text{cal\_min})\big)$ (flipped to $1 - x$ if `invert` is on). The calibrated **`3 %` rail zones** are **lower rail** $x \le 0.03$ (`CC 0..3` at `[0, 127]`) and **upper rail** $x \ge 0.97$ (`CC 124..127` at `[0, 127]`; `CC 122..125` with `125 = 1.0` at `[0, 125]`), and the **`6 %` origin-rail start band** (`D-8`) is $x \le 0.06$ in normal polarity (`CC 0..7` at `[0, 127]`) and $x \ge 0.94$ in reversed polarity (`CC 120..127` at `[0, 127]`), providing a `3 %` hysteresis deadband (`(0.03, 0.06]` normal / `[0.94, 0.97)` reversed) between throw start and origin-rail abort. Throw progress $t \in [0, 1]$ runs toward the active target rail ($x \ge 0.97$ in normal polarity; $x \le 0.03$ in reversed polarity when `bidirectional_flip` is on). **No timers exist anywhere in this state machine.**

## 6. Feel: Smoothing, Soft Takeover, and Controller Feedback (`R-FEEL-*`)

| ID | Phase | Requirement |
|---|---|---|
| `R-FEEL-1` | **Phase 1** | **30 ms Slew / Exponential Smoothing:** Every continuous fader slot runs a deterministic smoother (`src/core/smoother.c`) ticked on the OBS video thread (`obs_add_tick_callback`, `dt` in seconds) using exponential slew $\alpha = 1 - e^{-\Delta t / \tau}$ with configurable time constant $\tau \in [0\text{ ms}, 250\text{ ms}]$ (default **`30 ms`**; `0 ms` = instant bypass). Snaps cleanly to exact `0.0`, `1.0`, or target within `0.0005`. |
| `R-FEEL-2` | **Phase 1** | **Soft Takeover (Pick-Up Mode), Exact Calibrated Output Readout & Mode-Switch Reset:** If a target's live value in OBS changed externally, moving the physical fader MUST NOT jump the target.<br>• While `|fader_norm - target_norm| > pickup_threshold` (default `0.015`, ~2 MIDI steps), the slot enters `MFD_TAKEOVER_WAITING` and ignores fader changes while displaying a directional hint (`Move ▲` or `Move ▼`).<br>• Once a fader movement segment `[prev_norm, curr_norm]` crosses or lands within `pickup_threshold` of `target_norm`, it transitions to `MFD_TAKEOVER_ENGAGED` and tracks seamlessly.<br>• **Exact Calibrated Output Readout & Mode-Switch Reset (`D-12`):** The UI Output bar / live percentage readout equals the control's calibrated position $x$ (`last_raw_norm`) **exactly** ($\text{round}(x \times 100)$, e.g. `CC 51` of `127` = `40%`), never a carried-over rescale from another mode (and continues moving with the physical fader even while a precondition status sentence is showing and zero OBS writes occur). Switching a slot's mode resets its takeover and T-bar state cleanly to `Idle` (`WAITING`, `parked = false`, identity `[0, 1]` rescale origins, `polarity_reversed = false`, `tbar_state = MFD_TBAR_IDLE`). |
| `R-FEEL-3` | **Phase 5** | **Controller Lights & Bidirectional MIDI Out Feedback:** Sends dirty-checked MIDI Out updates to the controller: APC40 mkII SysEx Mode 2 (`0x42`) init, RGB clip-grid pads (Red = Program, Green = Preview, Cyan = Active Layer, Amber = Assigned), `A|B` bus LEDs (Off/Yellow/Orange), Track Mute/Activator LEDs (solid/off/blink on takeover wait), and Knob LED rings (`CC 48–55`, `CC 16–23`). |
| `R-FEEL-4` | **Phase 1** | **Rail Behavior — Parked State, Completion-Peak Tracking & 8 % Hysteresis Rescale:** Every continuous control has calibrated rails (`0 %` / `0.0` at `cal_min` and `100 %` / `1.0` at `cal_max`, `R-MIDI-5`), and reaching a rail enters a parked state (`MFD_TAKEOVER_PARKED`, exposed as `parked: true` in `get_state` / `state_changed`) with `8 %` hysteresis (cited by `R-FADE-1`, `R-TBAR-SM`, `R-FADE-2`, `R-MIX-1`, and `R-FADE-3`):<br>• **T-Bar Timer-Free Calibrated `3%` Rail Zone Release (`R-FADE-1`, `R-TBAR-SM`):** `MFD_TARGET_TBAR` follows the three-state machine (`Idle`, `Throwing`, `Parked`) in Section `5.1.1` with **zero timers anywhere**—driving the Studio Mode T-bar linearly across `[cal_min, cal_max]` and calling `obs_frontend_release_tbar()` once per throw **only** when the physical fader enters the target **`3 %` calibrated rail zone** ($x \ge 0.97$ normal polarity or $x \le 0.03$ reversed polarity) or on explicit API completion, then entering `Parked` with zero post-release slider writes.<br>• **Linear-to-End 3 % Rail Zone on Non-T-Bar Targets (`R-FADE-2`, `R-MIX-1`, `R-FADE-3`):** `crossfade_ab`, `layer_opacity`, and `audio_volume` stay strictly linear all the way to the calibrated ends (`0 % .. 100 %`; e.g., fader at `95 %` outputs `95 %`, fader at `97 %` outputs `97 %` — never snapping). Parking engages only inside the `3 %` calibrated rail zones ($x \ge 0.97$ at the top rail and $x \le 0.03$ at the bottom rail, including audio volume).<br>• **Peak Tracking, 8 % Hysteresis & Unpark Rescaling:** While `MFD_TAKEOVER_PARKED`, `parked_peak` tracks the furthest calibrated fader position reached toward that rail (`max` at the upper rail, `min` at the lower rail, advancing output linearly to `100 %` / `0 %` on non-T-bar targets as new extremes are reached).
