# Midi Fadester — Requirements

Status: 2026-10-27 (Phase 0 scoping and plan; awaiting operator approval before code).
Companion to [PLAN.md](PLAN.md); requirement IDs (`R-*`) and operator decisions (`D-*`) are referenced across the plan, test suite, and commit messages.

**Midi Fadester** (`midi-fadester.dll`) is a native C/C++ plugin for OBS Studio 33 on Windows x64 that turns class-compliant MIDI controllers—starting with the **Akai APC40 mkII**—into an **old-school hardware video mixer** (like a Panasonic WJ-MX50, Roland/Edirol V-4, or Resolume A/B layer desk). It gives direct, continuous fader control to **mix two or more live video sources simultaneously** via per-layer GPU opacity/luma/wipe filters, true A/B crossfader buses (`A|B` assign), dip-free crossfade curves, Studio Mode T-bar transitions, cubic-dB audio levels, arbitrary numeric filter settings, and RGB LED pad feedback.

## 4. WinMM MIDI I/O, Channel-Aware Learn, and Device Profiles (`R-MIDI-*`)

| ID | Requirement |
|---|---|
| `R-MIDI-1` | **WinMM Exclusive-Access Error Reporting (No Silent Fallback):** On Windows legacy `winmm` (`midiInOpen`), only one process can hold a MIDI input port open at a time (`MMSYSERR_ALLOCATED`). | `R-MIDI-2` | **Disconnect & Reconnect Resilience:** If an open MIDI controller is unplugged (`MIM_CLOSE` or `MMSYSERR_NODRIVER` / `MIDIERR_NODEVICE` on output), the plugin closes the stale WinMM handle cleanly on the UI thread, updates the UI status to *"Disconnected — waiting for <name>"*, and provides a one-click **Reconnect / Rescan** action (plus automatic 2-second rescan while disconnected). |
| `R-MIDI-3` | **Channel-Aware MIDI Addressing:** Every control binding is addressed by `(msg_type, channel, control_number)` where `msg_type` is `CC`, `NOTE`, or `PITCH_BEND`, `channel` is `0..15` (MIDI Channels 1–16), and `control_number` is `0..127`. Binding by CC number alone is forbidden because controllers like the Akai APC40 mkII send `CC 7` on Channels 1–8 for Track Faders 1–8. |
| `R-MIDI-4` | **One-Click MIDI Learn:** Clicking **Learn** on any mapping row enters a channel-aware capture state. Moving any hardware fader/knob or pressing any button/pad captures its `(msg_type, channel, control_number)` (and automatically detects whether a 14-bit CC MSB/LSB pair `CC 0..31` + `CC 32..63` is being transmitted on that channel), assigns it to the row, and exits Learn mode. |
| `R-MIDI-5` | **7-Bit and 14-Bit Continuous Resolution:** Standard 7-bit CC (`0..127`) normalizes to `[0.0, 1.0]` (`v / 127.0f`). When a controller sends 14-bit CC pairs (`CC 0..31` MSB + `CC 32..63` LSB on the same channel, `0..16383`) or 14-bit Pitch Bend (`0..16383`), the parser combines MSB and LSB into `[0.0, 1.0]` (`v / 16383.0f`). |
| `R-MIDI-6` | **Built-In Plug-and-Play Profile for Akai APC40 mkII:** Ships a built-in hardware profile for the **Akai APC40 mkII** (auto-selected when a MIDI device matching `"APC40 mkII"` is chosen, or selectable manually):<br>• **SysEx Mode Init (D-3):** Sends the official Akai Communications Protocol v1.2 Introduction message (`F0 47 7F 29 60 00 04 <mode> 01 00 00 F7`) on connect (`0x42` Alternate Ableton Live Mode by default so Device Knobs 1–8 remain on Channel 1 without track-bank shifting, or `0x40` Generic Mode if configured).<br>• **Track Faders 1–8 (`Ch 1–8, CC 7`):** 8 live Video/Audio Channel Strips (`Layer 1..8`). Raising multiple faders mixes multiple video sources on screen simultaneously.<br>• **Track `A|B` Crossfader Assign Buttons (`Ch 1–8, Note 66 / 0x42`):** Cycles Strip 1–8 between **Thru (Off, LED `0`)**, **Bus A (Yellow LED `1`)**, and **Bus B (Orange LED `2`)** for hardware A/B video bus mixing.<br>• **Crossfader (`Ch 1, CC 15`):** Configurable between **A/B Video Mixer Bus Crossfade** (mixes all Bus A layers against all Bus B layers, or direct Source A ↔ Source B) and **Studio Mode Program T-Bar**.<br>• **Master Fader (`Ch 1, CC 14`):** Master Program Opacity (Fade-to-Black) or Master Audio Level.<br>• **Track Knobs 1–8 (`Ch 1, CC 48–55`):** Per-strip Layer Mix Mode parameter (Luma Key threshold/softness, Wipe feather, or filter parameter) with LED ring feedback (`CC 56–63`).<br>• **Device Knobs 1–8 (`Ch 1, CC 16–23`):** Assigned Filter Numeric Settings (blur, color, zoom, etc.) with LED ring feedback (`CC 24–31`).<br>• **5×8 Clip Launch RGB Grid (`Ch 1, Notes 0–39`):** Per-column layer blend mode / source triggers or Scene Selection matrix with RGB velocity feedback.<br>• **Scene Launch 1–5 (`Ch 1, Notes 82–86`):** Quick Transitions, Cut, and Timed Fade-to-Black.<br>• **Track Activator / Mute Buttons (`Ch 1–8, Note 50`):** Source Mute or Layer Kill toggle for Strips 1–8 with LED feedback. |

## 5. Old-School Video Mixer Architecture: Mixing Two or More Sources (`R-MIX-*`)

This section captures the operator's core workflow: **mixing two or more live video sources together with faders like an old-school hardware video mixer (Panasonic WJ-MX50 / Edirol V-4 / Resolume), not merely fading a single source to black.**

| ID | Requirement |
|---|---|
| `R-MIX-1` | **Multi-Layer Channel Strip Mixing (2 to 8 Simultaneous Video Sources):** Any number of faders (e.g., APC40 mkII Track Faders 1–8) can be bound to individual video sources or nested scenes (`Playlister` sources, cameras, media sources, shader scenes). Raising 2, 3, or more faders at once composites all active layers together in real time without requiring Studio Mode. |
| `R-MIX-2` | **Single-Fader A/B Source Crossfader & Multi-Source Bus A ↔ Bus B Mixing:**<br>1. **Direct 1-Fader A/B Pair:** Any single fader or crossfader can be bound directly to **Source A ↔ Source B** (or an $N$-source chain **Source 1 → Source 2 → … → Source $N$**). Moving that one fader cross-mixes Source A (`100% → 0%`) and Source B (`0% → 100%`) simultaneously.<br>2. **A/B Crossfader Bus Matrix (`Bus A` ↔ `Bus B`):** Each of the 8 channel strips can be assigned to **Thru**, **Bus A**, or **Bus B** (via UI or the APC40 mkII `A|B` buttons `Note 66` on Ch 1–8 with Yellow/Orange LED feedback). A strip's effective opacity is:<br>$$\text{Opacity}_k = \text{StripFader}_k \times \text{BusGain}(\text{Bus}_k, x_{\text{xfade}})$$<br>This lets you stack multiple sources on Bus A, stack multiple sources on Bus B, balance each source with its vertical strip fader, and cross-mix the entire A and B stacks with the horizontal crossfader. |
| `R-MIX-3` | **Dip-Free Video Mixer Crossfade Curves (No Midpoint Fade-to-Black Dip):**<br>In standard Porter-Duff `Source Over` compositing over a black canvas, setting two stacked layers to `50%` opacity each yields $0.5 B + (1 - 0.5)(0.5 A) = 0.5 B + 0.25 A$ (a 25% brightness dip where black bleeds through). Our crossfader math (`src/core/mixer-math.c`) MUST provide selectable hardware video mixer curves:<br>1. **Dip-Free Dissolve (Default for Normal Overlay):** The lower layer holds `100%` opacity ($\alpha_A = \min(1, 2(1-t))$) while the upper layer dissolves in ($\alpha_B = t$), producing a true $A(1-t) + Bt$ optical crossfade with **zero black canvas bleed-through**.<br>2. **Full-Center Mix (`A = min(1, 2*(1-t))`, `B = min(1, 2*t)`):** At center (`t = 0.5`), **both Source A and Source B are at 100%**, ideal for Additive, Screen, Lighten (NAM), and Luma Key mixing.<br>3. **Equal-Power Cosine (`A = cos(t * pi/2)`, `B = sin(t * pi/2)`):** Constant-power perceptual crossfade.<br>4. **Linear Inverse (`A = 1 - t`, `B = t`):** Classic symmetric linear crossfade.<br>5. **Hard Cut / Scratch:** Steep cut at `t = 0.05 / 0.95`. |
| `R-MIX-4` | **Hardware Video Mixer Blend Modes & GPU Layer Modes (`mfd_layer_mixer.effect`):**<br>When Midi Fadester attaches its GPU filter (`"Midi Fadester — Layer Mixer"`, `id = "midi_fadester_opacity_filter"`) and manages the source's scene-item blending (`obs_sceneitem_set_blending_mode`), each layer supports classic hardware video mixer blend modes:<br>1. **Alpha Dissolve (`OBS_BLEND_NORMAL`):** Premultiplied RGBA scale (`rgba * opacity`).<br>2. **Non-Additive Mix / NAM (`OBS_BLEND_LIGHTEN`, `GS_BLEND_OP_MAX`):** Classic Panasonic WJ-MX50 / Edirol V-4 NAM mode — takes the brightest pixel (`max(A, B * opacity)`) so two video feeds combine without blowing out white levels.<br>3. **Additive (`OBS_BLEND_ADDITIVE`) & Screen (`OBS_BLEND_SCREEN`):** Scales RGB by `opacity` for energetic VJ overlays.<br>4. **Multiply (`OBS_BLEND_MULTIPLY`) & Darken (`OBS_BLEND_DARKEN`):** Texture/shadow compositing.<br>5. **Luma Key Fader Mode (Bright Key / Dark Key):** Built into `data/effects/mfd_layer_mixer.effect`. As the fader moves from `0.0 → 1.0`, the luminance key threshold sweeps smoothly (with configurable softness) so bright highlights (or dark silhouettes) of Source B key over Source A first, then complete to a full frame at `1.0`—matching the Luma Key fader on a hardware video mixer.<br>6. **Geometric Wipe Fader Mode (Horizontal, Vertical, Radial Circle, Box):** Built into `data/effects/mfd_layer_mixer.effect`. Moving a layer fader `0.0 → 1.0` wipes the source across the frame over any underlying sources with adjustable soft-edge feathering. |

## 6. All Fader and Button Target Types (`R-FADE-*`)

| ID | Target Type | Requirement & OBS 33 Mechanism |
|---|---|---|
| `R-FADE-1` | **Program Crossfade (Preview to Live T-Bar)** | Drives the Studio Mode transition T-bar (`0..1023`).<br>• **Studio Mode Gate (Crash Prevention):** Verified in OBS 33.0.0 source (`OBSBasic.hpp:1519`, `OBSBasic_StudioMode.cpp:259`, `OBSStudioAPI.cpp:120`, `OBSBasic_Transitions.cpp:752`): `OBSBasic::tBar` is an uninitialized or deleted raw `QSlider *` whenever Studio Mode is off, so calling `obs_frontend_get_tbar_position()` or `obs_frontend_release_tbar()` while Studio Mode is off crashes OBS. The plugin MUST check `obs_frontend_preview_program_mode_active()` before every T-bar call and display *"Studio Mode is off — enable Studio Mode to use the T-bar (or switch crossfader to A/B Layer Bus mode)"* when inactive.<br>• **Release-Cancellation Bug Fix (Code-Verified):** In OBS 33.0.0 (`OBSStudioAPI.cpp:115-118`), `obs_frontend_set_tbar_position(pos)` invokes `OBSBasic::TBarChanged(pos)` without updating `tBar->setValue(pos)`. Because `tBar->value()` stays `0`, calling `obs_frontend_release_tbar()` reads `val = 0 <= T_BAR_CLAMP` and cancels the transition back to the previous scene. To fix this cleanly, when Studio Mode is active the plugin drives the Studio Mode `tBar` `QSlider` (`property("class") == "slider-tbar"`) on the Qt UI thread via `setValue(pos)` and invokes `obs_frontend_release_tbar()` when the smoothed fader reaches the completion rail (`<= 2` or `>= 1021`), completing the transition and swapping Preview/Program scenes cleanly.<br>• **Bidirectional Switcher Throw (D-2):** Defaults to video-switcher auto-flip mode so throwing `0 → 127` completes one transition (`0 → 1023`) and throwing `127 → 0` completes the next transition (`0 → 1023`). |
| `R-FADE-2` | **Layer Fade & Multi-Source Video Mixer (`mfd_opacity_filter`)** | Fades any individual video source or nested scene (`0.0% .. 100.0%`), or cross-mixes 2+ sources via `R-MIX-1 .. R-MIX-4`, independent of Studio Mode.<br>• **Dedicated Plugin Filter:** Registers `"Midi Fadester — Layer Mixer"` (`id = "midi_fadester_opacity_filter"`, `OBS_SOURCE_TYPE_FILTER`, `OBS_SOURCE_VIDEO`). When a source is assigned to a Layer Strip or A/B Crossfader, the plugin looks up or auto-attaches an instance named `"__midi_fadester_opacity__"` via `obs_source_get_filter_by_name` / `obs_source_filter_add`, leaving all of the user's existing filters untouched.<br>• **Zero Overhead at 100% Alpha:** When in Alpha Dissolve mode and `opacity >= 0.999f`, `video_render` calls `obs_source_skip_video_filter` for zero GPU cost. |
| `R-FADE-3` | **Audio Level (OBS Cubic dB Curve)** | Controls any audio source's volume (`obs_source_set_volume`) using OBS's exact `OBS_FADER_CUBIC` law (`libobs/obs-audio-controls.c:81-99`):<br>• Deflection $d \in [0.0, 1.0]$ maps to linear amplitude multiplier $\text{mul} = d^3$ ($\text{dB} = 60 \log_{10}(d)$, with $d = 0 \implies \text{mul} = 0, -\infty\text{ dB}$ and $d = 1 \implies \text{mul} = 1, 0.0\text{ dB}$).<br>• Inverse mapping for soft takeover and LED ring feedback reads `obs_source_get_volume(source)` and computes $d = \sqrt[3]{\text{mul}}$ (`cbrtf`).<br>• Optional **Audio-Follows-Video (AFV)** checkbox per layer strip so fading a video source in/out optionally crossfades its audio along the cubic curve. |
| `R-FADE-4` | **Any Numeric Filter Setting** | Drives any numeric property (`OBS_PROPERTY_FLOAT` or `OBS_PROPERTY_INT`) on any filter attached to any source or scene (e.g., Color Correction saturation/hue/contrast/gamma, Crop/Pad, NVIDIA RTX Blur / Background Blur `intensity`, NVIDIA Background Removal `threshold`, or Visual Sidechain parameters).<br>• Uses `obs_weak_source_t` references, maps normalized fader travel `[0.0, 1.0]` to user `[min_val, max_val]`, batches updates per filter once per video tick, and gates `obs_source_update` with an epsilon threshold (`|new_val - last_sent_val| >= 0.001`) so untouched faders generate zero `obs_source_update` calls. |
| `R-FADE-5` | **Buttons, Scene Grid, Hotkeys & Timed Fade-to-Black** | Maps MIDI Note On/Off and button CCs to:<br>1. **A|B Crossfader Bus Assign (`Thru / Bus A / Bus B`)** and **Layer Blend Mode Select (`Normal / NAM-Lighten / Add / Screen / Luma Key / Wipe`)**.<br>2. **Select Preview Scene** (`obs_frontend_set_current_preview_scene`) or **Switch Program Scene** (`obs_frontend_set_current_scene`).<br>3. **Trigger Transition** (`obs_frontend_preview_program_trigger_transition`).<br>4. **Timed Fade to Black over $N$ ms:** Toggles fade-to-black on output channel 0 (`obs_get_output_source(0)`) over configurable `duration_ms` (default `500 ms`, range `50..10000 ms`) via `obs_transition_start(transition, OBS_TRANSITION_MODE_AUTO, duration_ms, NULL)` and restores the previous Program scene on the next trigger.<br>5. **Audio Mute Toggle / Push-to-Mute / Push-to-Talk** (`obs_source_set_muted`).<br>6. **Scene Item Visibility / Layer Solo / Layer Flash (Momentary 100%)**.<br>7. **Stream / Record / VirtualCam / Replay Buffer** start, stop, or toggle.<br>8. **Any Registered OBS Hotkey:** Enumerated via `obs_enum_hotkeys` and triggered on the Qt UI thread via `obs_hotkey_trigger_routed_callback(id, pressed)` for both press (`true`) and release (`false`). |

## 7. Feel: Smoothing, Soft Takeover, and Controller Feedback (`R-FEEL-*`)

| ID | Requirement |
|---|---|
| `R-FEEL-1` | **30 ms Slew / Exponential Smoothing:** 7-bit MIDI (`128` steps) produces visible stair-stepping on slow video and filter fades. Every continuous fader slot runs a deterministic smoother (`src/core/smoother.c`) ticked on the OBS video thread (`obs_add_tick_callback`, `dt` in seconds) using exponential slew $\alpha = 1 - e^{-\Delta t / \tau}$ with configurable time constant $\tau \in [0\text{ ms}, 250\text{ ms}]$ (default **`30 ms`**; `0 ms` = instant bypass). When within `0.0005` of `0.0`, `1.0`, or the target, it snaps cleanly to the exact value. |
| `R-FEEL-2` | **Soft Takeover (Pick-Up Mode):** If a target's live value in OBS was changed outside the fader (by mouse in OBS, scene switch, or preset load), moving the physical fader MUST NOT jump the target.<br>• While `|fader_norm - target_norm| > pickup_threshold` (default `0.015`, ~2 MIDI steps), the slot enters `MFD_TAKEOVER_WAITING` and ignores incoming fader changes while displaying a directional hint (`Move ▲` or `Move ▼` to pick up).<br>• As soon as a fader movement segment `[prev_norm, curr_norm]` crosses or lands within `pickup_threshold` of `target_norm`, the slot transitions to `MFD_TAKEOVER_ENGAGED` and tracks the fader seamlessly.<br>• When OBS changes the target externally while the fader has been idle for `> 150 ms`, the slot automatically re-arms `MFD_TAKEOVER_WAITING`. |
| `R-FEEL-3` | **Controller LED & Ring Feedback:** Tracks live OBS state changes (`SCENE_CHANGED`, `PREVIEW_SCENE_CHANGED`, `STUDIO_MODE_ENABLED/DISABLED`, `STREAMING_*`, `RECORDING_*`, source `mute` and `volume` signals, and `A|B` bus assignments) and transmits dirty-checked MIDI Out updates:<br>• **APC40 mkII 5×8 RGB Grid:** Program scene pad = **Red (`vel 5`)**, Preview scene pad = **Green (`vel 21`)**, active video layer = **Cyan (`vel 37`)**, other mapped pads = **Amber (`vel 9`)**, unassigned = **Off (`vel 0`)**.<br>• **APC40 mkII `A|B` Buttons (`Note 66`, Ch 1–8):** Off (`0`) = Thru, Yellow (`1`) = Bus A, Orange (`2`) = Bus B.<br>• **APC40 mkII Track Mute / Activator (`Note 50`, Ch 1–8):** Lit (`1`) when strip/source is active, Off (`0`) when muted/killed; blinks (`2`) when waiting for soft-takeover pickup on that strip.<br>• **APC40 mkII Knob Rings (`CC 48–55`, `CC 16–23`):** Updated with `0..127` position when the bound target changes in OBS. |

## 8. Threading, Testing, and Working Rules (`R-THR-*`, `R-TST-*`, `R-STD-*`)

| ID | Requirement |
|---|---|
| `R-THR-1` | **Three-Thread Safety Contract:**<br>1. **WinMM Callback Thread (`midiInProc`):** Strictly real-time and lock-free. Parses `MIM_DATA` bytes and pushes fixed-size `mfd_midi_event_t` structs into a lock-free Single-Producer Single-Consumer (SPSC) ring buffer (`src/core/midi-queue.c`). Zero heap allocations, zero mutexes, zero OBS API calls, and zero WinMM calls inside `midiInProc` (calling `midiIn*`/`midiOut*` inside `midiInProc` deadlocks Windows `winmm.dll`).<br>2. **OBS Video Tick Thread (`obs_add_tick_callback`):** Drains the SPSC MIDI queue, updates 14-bit CC state, evaluates soft takeover, A/B crossfader bus math, and the 30 ms smoother (`dt`), applies Layer Mixer filter values, Audio Levels (`obs_source_set_volume`), and batched Filter Modulator updates (`obs_source_update`), and queues Qt-thread actions when needed.<br>3. **Qt UI Thread:** Executes `obs_frontend_*` calls (T-bar slider updates/release, scene switches, transitions, hotkeys via `QMetaObject::invokeMethod` / `obs_queue_task(OBS_TASK_UI, ...)`), manages the Midi Fadester Dock / Dialog UI, and opens/closes WinMM devices. |
| `R-TST-1` | **Headless Pure-C Unit Test Suite (`ctest`):** All core logic in `src/core/` MUST be pure C17 with zero OBS or WinMM dependencies and tested via `ctest` using synthetic and recorded MIDI streams:<br>• `test-midi-parser`: 7-bit CC, 14-bit MSB/LSB CC pairing, channel separation (APC40 mkII `CC 7` across Ch 1–8), Note On/Off (`vel 0` as Note Off), Pitch Bend, MIDI Learn capture.<br>• `test-smoother`: 30 ms exponential slew step response, frame-rate independence (`30/60/120 fps`), exact endpoint snap at `0.0` and `1.0`, `0 ms` instant mode.<br>• `test-takeover`: Pick-up waiting when OBS value diverges, upward crossing, downward crossing, external value jump re-arming, bidirectional T-bar throw flip.<br>• `test-mixer-math`: Dip-free dissolve (`A = min(1, 2*(1-t)), B = t`), Full-Center mix (`A = 1, B = 1` at `t = 0.5`), Equal-Power cosine, N-source chain crossfader, 8-strip `Thru / Bus A / Bus B` matrix calculation, OBS cubic audio curve (`def^3` and `cbrtf(mul)` round-trip).<br>• `test-apc40-profile`: APC40 mkII default map lookup, `A|B` bus button cycling, SysEx Introduction packet bytes (`F0 47 7F 29 60 00 04 42 01 00 00 F7`), dirty-checked RGB LED feedback state machine.<br>• `test-midi-queue`: Lock-free SPSC ring buffer wrap-around, full-queue drop counter, burst replay of recorded MIDI fader sweeps. |
| `R-TST-2` | **Portable OBS 33 Live Harness Verification:** Automated and interactive verification in `C:\Users\jeffr\OBS-Studio-33-Portable` (started with working directory `bin\64bit`, closed cleanly via `CloseMainWindow`): verifies clean plugin load without `Legacy` badge, multi-layer 2+ source mixing, A/B crossfader bus mix, T-bar crossfade completion and Studio Mode off safety, `mfd_layer_mixer.effect` shader compilation (Alpha, Luma Key, Wipe), and clean shutdown with zero memory leaks (`obs_get_num_leaks() == 0`). |
| `R-STD-1` | **Code & Repo Hygiene:**<br>• Plan first (`REQUIREMENTS.md` and `PLAN.md`) and wait for operator approval before writing plugin code.<br>• Run the full test suite (`ctest`) after every code change without being asked.<br>• UTF-8 without BOM in every file; zero 0-byte files; meaningful identifiers; never use the banned placeholder word (`d-u-m-m-y`; use `placeholder` or `stub`); no profanity anywhere.<br>• Format C/C++ with `clang-format` and CMake with `gersemi` rules (2-space indent, 120 columns).<br>• Maximum one `git push` attempt per cycle; verify `HEAD == origin/main`, zero 0-byte files, and zero BOMs after every push. |
